# agent-wallet-il — ארנק תשלום מבוקר לסוכני AI 🤖💳

**הסוכן שלך רוצה לקנות בשמך. אתה רוצה שהוא לא יקנה בשמך בלי הגבלה.**
הפרויקט הזה הוא שכבת הבקרה שביניהם: ארנק נטען עם חוקים, בקוד פתוח, בעברית, לארץ.

הרעיון עלה משיחה פשוטה: *"כרטיס אשראי מוגבל, נטען ידנית בלבד, לבוטים — אני רוצה לתת לבוט שלי אשראי שיקנה בשמי אבל לא את שלי"*. בארה״ב כבר יש [Allowance](https://useallowance.com/) (YC) שעושה בדיוק את זה — אישור בטלפון לכל קנייה ואז אישור תשלום חד־פעמי — אבל השירות זמין שם בלבד. אז בנינו גרסה ישראלית, פתוחה, שכל אחד יכול להריץ, לבדוק ולשפר.

## מה זה עושה

- **ארנק נטען ידנית** — אין חיבור לכרטיס האשראי הראשי שלך. מה שהפקדת, זה מה שיש.
- **חוקי הוצאה** — תקרה לרכישה בודדת, תקרה יומית, תקרה חודשית, רשימת בתי עסק מותרים וחסומים.
- **אישורי תשלום חד־פעמיים** — אחרי אישור מונפק אישור נעול לבית העסק ולסכום המדויק, פג תוקף אחרי 10 דקות, לשימוש יחיד. הסוכן אף פעם לא רואה כרטיס אמיתי.
- **חיבור לסוכנים** — שרת MCP (עובד עם Claude, Cursor, וכל סוכן שתומך ב־MCP) + REST API פשוט.
- **פנקס תנועות מלא** — כל טעינה, אישור ודחייה מתועדים.

## שני מצבי עבודה — הבחירה שלך

יש שתי פילוסופיות, והפרויקט לא בוחר בשבילך:

1. **`approve-each` — אישור לכל קנייה** (הגישה של Allowance): הסוכן מבקש, אתה מאשר בלחיצה, רק אז מונפק אישור תשלום.
2. **`autonomous` — אוטונומי בתוך תקציב** (הכיוון המקורי): טענת ₪200, הגדרת חוקים, והסוכן קונה בעצמו כל עוד הוא בתוך התקציב והחוקים. בלי שאלה לכל קנייה — בלי חריגה מהתקרה.

המעבר בין המצבים הוא שורת קוד אחת או לחצן בדמו.

## ⚠️ מה זה *לא* — ומה הדרך לכסף אמיתי

**הגרסה הזו היא הדמיה.** אישורי התשלום הם אסימונים מדומים; שום כסף אמיתי לא זז. הליבה (החוקים, התקציב, האישורים) אמיתית ונבדקת — המסילה הכספית לא.

כדי להפוך את זה לכסף אמיתי צריך **מנפיק או סולק שחושף API להנפקת כרטיסים וירטואליים עם בקרות** (נעילה לבית עסק, תקרות, ביטול מיידי). חשוב להבין: בקרות שרצות רק בקוד הלקוח לא שוות כלום ברגע שהסוכן מחזיק מספר כרטיס גולמי — הבקרה חייבת לשבת אצל המנפיק.

מה שאנחנו יודעים היום (נבדק מול מקורות רשמיים, אוקטובר 2026):

- **מועמד מוביל, עוד לא מאומת: Airwallex Issuing.** עסקים רשומים בישראל זכאים לכרטיסי חברה/עובדים ב־Airwallex ([טבלת הזכאות הרשמית](https://help.airwallex.com/hc/en-gb/articles/4411298079129-What-features-and-products-are-available-in-my-registered-business-location)), ותיעוד ה־API מפרט [ישראל כאזור הנפקה](https://www.airwallex.com/docs/issuing/supported-card-programs) עם תוכנית דביט מסחרית **נטענת־ארנק** ו[חיוב ישיר ב־₪](https://www.airwallex.com/docs/issuing/supported-regions-and-currencies), וכן [כרטיס חד־פעמי, מטבעות מותרים, MCC מותרים, מגבלות סכום ואישור מרחוק](https://www.airwallex.com/docs/issuing/card-controls/authorization-controls). **אבל:** זה מוכיח רק כרטיסי הוצאות עסקיים לעובדים שלך — לא הנפקת פלטפורמה לצרכנים/סוכנים עצמאיים. לא אומתו: זכאות עצמית ל־Issuing API בלי אישור תוכנית, תוכנית צרכנית/פלטפורמה (דורשת אישור), בקרות נעילה לבית־עסק מסוים (מול MCC בלבד), בידוד יתרות לכל סוכן, עלויות, וזכאות עוסק/יחיד.
- **Stripe Issuing לא זמין לישראל.** ההנפקה המקומית שלהם פועלת ב־[22 מדינות בלבד](https://docs.stripe.com/issuing/global) (אירופה, בריטניה, קנדה) — ישראל לא ברשימה, וההנפקה חוצת־הגבולות שלהם בגישה מוקדמת לחברות רב־לאומיות.
- **Wise Platform** חושפת [API להנפקת כרטיסים עם בקרות](https://docs.wise.com/guides/product/issue-cards), אבל זה מוצר שותפים (בנקים וארגונים) עם זכאות מותנית במכירות; לא אומת ששותף יכול להנפיק לתושבי ישראל. כרטיס ה־Wise הצרכני עצמו [זמין לתושבי ישראל](https://wise.com/help/articles/2968915/can-i-get-the-wise-card-in-my-country) (דביט נטען, לא אשראי) — אבל בלי API אישי.
- **Apple Pay / Google Pay לא פותרים את הבעיה.** אין בהם ממשק שמאפשר לסוכן לחייב מהארנק האישי שלך; תשלום שיזם המשתמש דורש אישור על המכשיר (בתשלומים חוזרים אצל סוחר מאושר יש [merchant tokens של אפל](https://developer.apple.com/apple-pay/merchant-tokens/) ו־[MIT של גוגל](https://developers.google.com/pay/api/web/guides/resources/merchant-initiated-transactions), אבל זה חיוב יזום־סוחר תחת חוקי הרשת, לא רail חופשי לסוכן). והכנסת כרטיס שהפרויקט מנפיק לתוך הארנקים פתוחה [רק למנפיקים מורשים](https://applepaypartners.apple.com/issuers/features/in-app-provisioning).
- **סולקים ישראליים** (קארדקום, טרנזילה ועמיתים) מציעים API לסליקה — מתאימים לצד *הטעינה* של הארנק, לא להנפקת כרטיסים.

בשורה התחתונה: הבקרה פה, הכסף עוד לא. יש מועמד מנפיק ראשון (Airwallex) שאומת לשימוש עסקי ישראלי — התאמה למודל צרכני/פלטפורמה עוד לא אומתה.

## הרצה בדקה

דרוש Node.js 22+ (מריץ TypeScript ישירות, אפס תלויות, אפס build).

```bash
git clone https://github.com/ofershap/agent-wallet-il
cd agent-wallet-il

# מרים שני ערוצים: סוכן ב-:3000, בעלים ב-:3001
npm start

# בדיקות
npm test

# שרת MCP לסוכן שלך (ערוץ סוכן בלבד)
npm run mcp
```

- **ערוץ סוכן** `http://localhost:3000` — `GET /api/state`, `POST /api/request`, `POST /api/redeem`. זה הכל: אין בפורט הזה טעינה, אישור או שינוי חוקים.
- **ערוץ בעלים** `http://localhost:3001` — מסוף ניהול + כל פעולות הבעלים. כל קריאת API דורשת כותרת `x-owner-token`. הגדירו `OWNER_TOKEN` במשתנה סביבה, או שהשרת ידפיס אסימון זמני ל-console בכל עלייה.
- אפשר גם פשוט לפתוח את `demo/index.html` בדפדפן — דמו ויזואלי עצמאי שעובד בלי שרת בכלל.

### חיבור לסוכן (MCP)

```json
{
  "mcpServers": {
    "agent-wallet-il": {
      "command": "node",
      "args": ["/path/to/agent-wallet-il/src/mcp-server.ts"]
    }
  }
}
```

כלים (ערוץ סוכן בלבד): `get_balance`, `request_spend`, `list_requests`, `get_ledger`, `redeem_credential`.

> **ההפרדה נאכפת בקוד, לא בתיעוד:** `approve_spend`, `top_up` ו־`set_rules` פשוט לא קיימים בשרת ה־MCP. פעולות בעלים זמינות רק בערוץ הבעלים (פורט 3001) מאחורי `OWNER_TOKEN` — ובעתיד, ממספר הוואטסאפ המאומת של הבעלים.

## דוגמת קוד

```ts
import { AgentWallet } from './src/wallet.ts';

const wallet = new AgentWallet('autonomous', {
  perPurchaseAgorot: 5000,   // ₪50 לקנייה
  dailyAgorot: 10000,        // ₪100 ליום
  monthlyAgorot: 30000,      // ₪300 לחודש
});

wallet.topUp(20000);                                    // טענת ₪200 ידנית
const { request, credential } = wallet.requestSpend('איקאה', 4500, 'מנורת קיר');
// בתוך החוקים? credential חד־פעמי נעול ל־IKEA בסך ₪45, פג בעוד 10 דקות.
// מחוץ לחוקים? request.status === 'auto-declined' עם הסיבה.
```

## ארכיטקטורת אבטחה

1. **שני ערוצים, נאכף בשרת.** סוכן ובעלים לא חולקים ערוץ. גם אם הסוכן "יודע" על אישורים — אין לו נתיב אליהם.
2. **אישור = רזרבציה.** ברגע שמונפק אישור תשלום, הסכום נעול (hold): הוא מקוזז מהיתרה הזמינה ומתקרות היום/חודש, כך שאי אפשר לאשר פעמיים את אותו הכסף — גם לא בשתי בקשות מקבילות. אישור שפג תוקפו משחרר את הרזרבציה אוטומטית.
3. **אישור חד־פעמי ונעול.** אסימון קשור לבית עסק ולסכום מדויקים, פג אחרי 10 דקות, ונכשל במימוש חוזר, במסחר אחר או בסכום אחר.
4. **אימות קלט.** סכומים הם אגורות — מספרים שלמים וחיוביים בלבד, נבדק בכל נתיב.

**גבולות הדמו (אמורים בפירוש):**
- המצב נשמר בזיכרון בלבד — הפעלה מחדש מאפסת את הארנק.
- אין TLS ואין אימות מעבר ל־`OWNER_TOKEN`; מיועד ל-localhost בלבד, לא לפריסה פומבית.
- תהליך יחיד — אין התמודדות עם כמה תהליכים על אותו ארנק.
- אישורי התשלום מדומים ואינם מנפיקים כסף אמיתי.

## מבנה

```
src/wallet.ts      הליבה — חוקים, תקציב, רזרבציות, פנקס (טהור, אפס I/O)
src/issuer.ts      גבול המתאם למנפיק (IssuerAdapter) + הדמיה מקומית; מתאם אמיתי יתחבר כאן
src/mcp-server.ts  שרת MCP — ערוץ סוכן בלבד
src/server.ts      שני שרתי REST: סוכן :3000, בעלים :3001 (x-owner-token)
demo/index.html    דמו ויזואלי עצמאי (עובד גם בלי שרת)
demo/owner.html    מסוף הבעלים שמוגש מפורט 3001
test/              node:test — חוקים, רזרבציות, קצוות, מתאם (14 בדיקות)
```
